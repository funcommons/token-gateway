# 前端开发规范 (Frontend Development Specification)

---

## 1. 原则 (Principles)

### 1.1 路由模式 (Routing)

- **HTML5 History 模式**：所有项目必须采用 HTML5 History 模式进行路由管理，禁止使用 Hash 模式。
- **服务端配合**：生产环境部署时，Nginx 等 Web 服务器必须配置 `try_files $uri $uri/ /index.html`，以避免页面刷新时出现 404 错误。

### 1.2 国际化多语言 (Internationalization)

- **默认支持**：项目在架构设计之初必须集成国际化（i18n）支持，默认内置中英双语（`zh-CN` / `en-US`）。
- **静态文本规范**：代码中禁止直接硬编码中文字符串，所有 UI 文本均需通过 `t('key')` 函数获取。
- **语言切换**：支持即时无刷新切换语言，切换后需持久化至 LocalStorage。

### 1.3 主题动态更换 (Theme Switching)

- **动态配置**：主题必须支持动态无刷新更换。所有组件样式均需基于 CSS 变量（CSS Variables）进行驱动。通过 `html[data-brand]` 和 `html[data-theme]` 属性切换。
- **主题维度**：主题切换由 **品牌 (Brand)** + **配色 (Theme)** 共同决定。
  - **品牌 (Brand)**：决定圆角、阴影、字体、主色等视觉风格。当前默认品牌：`mchuan`。
  - **配色 (Theme)**：决定明暗背景、文字色、边框色等。当前已入册 3 种配色：`light` / `dark` / `orange-black`。

### 1.4 响应式设计 (Responsive Design)

- **设备兼容**：必须无缝兼容电脑端（Desktop）、平板端（Tablet）与手机端（Mobile）。
- **断点标准**：

  | 设备 | 断点 |
  |------|------|
  | 手机端 (Mobile) | `screen < 768px` |
  | 平板端 (Tablet) | `768px <= screen < 1024px` |
  | 电脑端 (Desktop) | `screen >= 1024px` |

- **交互适配**：交互元素必须同时支持鼠标指针与高精度的触控操作（最小点击热区推荐为 44px x 44px）。

## 2. 技术栈 (Technology Stack)

技术栈管理实行"已入册"与"审核入册"双轨制。任何非"已入册"技术或库在项目中使用前，必须提交技术委员会审核，通过后方可登记入册。

```
├── 已入册 (已通过全面评估，推荐在所有项目中使用)
│   ├── TypeScript   (静态类型安全，全面启用严格模式)
│   ├── Vue 3        (组合式 API Setup 语法糖)
│   ├── Element Plus (版本 2.14.1，用于基础 UI 组件)
│   └── micro-app    (微前端框架，实现子应用聚合)
└── 可选/要审核入册 (需向架构组发起评审，通过后方可引入)
    └── 任何其他第三方工具库 (如特定图表库、动效库、状态管理替代方案等)
```

## 3. 布局 (Layout)

### 3.1 统一布局模式

根据业务场景，项目需在以下三种基础布局模式中进行选择：

| 模式 | 结构 | 场景 |
|------|------|------|
| **APP 模式** | AppHeader + AppSidebar + AppMain | 复杂的系统主界面，需要强导航与多级功能管理 |
| **模块模式** | AppSidebar + AppMain | 特定子系统、控制面板、或二级模块内部 |
| **单页模式** | AppMain (独占) | 大屏看板、数据报表、表单向导、全屏编辑器或独立营销页 |

### 3.2 核心布局组件与约束

```
┌──────────────────────────────────────────────────────────────┐
│                          AppHeader                           │
├────────────┬─────────────────────────────────────────────────┤
│            │  [ToolBar]                                      │
│            │  ┌────────────────────────────────────────────┐ │
│            │  │                  Section 1                 │ │
│ AppSidebar │  ├────────────────────────────────────────────┤ │
│            │  │                  Section 2                 │ │
│            │  └────────────────────────────────────────────┘ │
│            │  [FooterBar]                   [RightSidebar]   │
└────────────┴─────────────────────────────────────────────────┘
```

#### 3.2.3 工作区 (AppMain)

- **核心内容区**：工作区是页面功能承载的主体。
- **严格的嵌套约束**：
  - **工作区中只能放置**：功能块 (Section)、工具栏 (ToolBar)、底部栏 (FooterBar)、右侧栏 (RightSidebar) 和布局组件。
  - **样式圆角与阴影**：工作区的圆角、边框和阴影等变量，是不同风格主题切换的核心受控变量。工作区内部的组件不得再次出现与工作区完全相同或嵌套的功能区块线框，避免"套娃"视觉。
  - **对齐原则**：工作区内的所有组件和内容，**必须默认靠左（left）对齐**，禁止无故居中对齐。

> **铁律**：Section 内不能套 Section，工作区内不能再出现"区块类"外框。

##### 全局变量（mchuan + light 默认）

| 变量 | 默认值 | 用途 |
|------|--------|------|
| `--app-main-bg` | `#f5f7fa` | 工作区背景（浅灰，区分于 sidebar 白底） |
| `--app-main-padding-x` | `16/8/4px` | 水平内边距（响应式，同 §3.4） |
| `--app-main-padding-y` | `16/8/4px` | 垂直内边距（响应式） |
| `--app-main-block-gap` | `16/8/4px` | 子区块间距（响应式） |

#### 3.2.4 布局组件（工作区内）

- **间距归零**：在工作区内使用的布局组件（如 `el-row`、`el-col`、`el-tabs` 等），其 padding 和 margin 必须全部设置为 0。
- **特殊可视化布局（如 Tabs）**：
  - 若布局组件含有可视化边框或背景（如卡片样式的 Tabs），其可视化外框和样式表现必须与功能块 (Section) 保持高度一致。
  - Tabs 组件的 content 容器部分的 padding 和 margin 必须强制设为 0，内部内容由子组件功能块自行撑开或根据规范自适应。

```scss
/* 布局组件在工作区内必须 0 间距 */
.app-main {
  .el-row,
  .el-col,
  .el-tabs__content {
    padding: 0 !important;
    margin: 0 !important;
  }
}
```

#### 3.2.5 功能块 (Section)

- **原子性**：功能块是页面中最小的可视化视觉区块，包含独立的白色/浅色背景、圆角及阴影。
- **嵌套限制**：功能块**只能**存放在工作区或工作区下的布局组件中，且**绝对禁止相互嵌套**（功能块内不能再包含子功能块）。
- **内部去线框化**：功能块内部不允许再出现区块类的边框线（如 Form 表单区域外部不得再包围一圈实线或虚线外框），但允许并仅限于使用输入类组件自带的边框（如 `el-input` 的输入框线）。

> 输入类型组件（el-input / el-select / el-textarea / el-button / el-tag / el-switch / el-checkbox / el-radio）的边框保留，因为它们是**字段边框**而非**区块边框**。

#### 3.2.6 工具栏 (ToolBar)、底部栏 (FooterBar)、右侧栏 (RightSidebar)

- **数量限制**：上述组件只能存放在工作区中，且在同一个工作区内**最多只能各出现一个**。
- **磁吸定位**：在任何设备环境下，它们必须分别牢固磁吸在对应的边缘（工具栏磁吸在工作区顶部、底部栏磁吸在工作区底部、右侧栏磁吸在工作区右侧）。
- **右侧栏的响应式适配**：
  - 在**手机端**时，右侧栏必须收缩隐藏为一个漂浮的图标（Trigger Button），用户点击该图标后，以抽屉（Drawer）形式从右侧向左展开。

```scss
.app-main {
  position: relative;

  .app-toolbar   { position: sticky; top: 0;     }  // 顶部
  .app-footerbar { position: sticky; bottom: 0;  }  // 底部
  .app-rightbar  { position: sticky; right: 0;   }  // 右侧
}
```

### 3.3 侧边栏菜单三种模式规范

为保障跨端体验的一致性与操作便利性，侧边栏（AppSidebar）在不同设备和状态下，必须在以下三种模式中进行流转：

#### 3.3.1 模式定义

| 菜单模式 | 视觉宽度 | 交互行为 | 适用环境与默认行为 |
|:---------|:---------|:---------|:-------------------|
| **侧边抽屉模式** (Drawer) | 平时隐藏 | 菜单默认完全隐藏。视口左上角显示一个菜单触发按钮。点击按钮，弹出遮罩抽屉式菜单。 | **手机端** 默认且唯一强制此模式。平板与电脑端在极限窄屏下可自动降级为此模式。 |
| **侧边图标模式** (Icon Mini) | 固定 64px | 仅显示一级菜单的 Icon 图标。Hover 图标浮动显示菜单名称。Click 图标侧边弹出二级菜单弹窗。底部有"展开"按钮。 | **平板端** 默认此模式。电脑端可由用户手动点击缩进切换至此模式。 |
| **侧边菜单模式** (Full Expanded) | 200-400px（可拖动缩放） | 完整展示多级树状菜单。底部有"折叠"按钮。边缘支持鼠标拖拽改变宽度（限制最小宽 200px，最大宽 400px）。 | **电脑端** 默认此模式。手机与平板端禁止作为默认常驻模式。 |

**模式流转规则：**

```
手机端 (< 768px)        → 强制 Drawer 模式 (无其他选择)
平板端 (768-1023px)     → 默认 Icon Mini, 用户可手动切到 Full
电脑端 (≥ 1024px)       → 默认 Full Expanded, 用户可手动切到 Icon Mini
```

#### 3.3.2 导航与状态保持逻辑

- **默认折叠原则**：当页面首次加载、路由发生跳转或手动刷新时，侧边菜单中**非当前激活路由**的菜单项默认必须处于收起/折叠状态。
- **精准激活**：只有当前页面路径（Active Route）所对应的菜单项及其所有父级菜单，才在初始化时被高亮选中并默认展开。
- **状态持久化**：用户在电脑端手动选择的"折叠（Icon）/ 展开（Full）"偏好，需记录在 LocalStorage 中，后续访问同一设备时保持该偏好，但需受限于屏幕尺寸响应式底线。

```typescript
// 状态持久化: 折叠/展开偏好存 LocalStorage
const preference = usePreferenceStore()
preference.sidebarCollapsed  // true = Icon Mini, false = Full Expanded
localStorage.setItem('sidebarCollapsed', String(preference.sidebarCollapsed))
```

### 3.4 响应式间距与栅格规范

#### 3.4.1 工作区弹性间距 (Responsive Spacing)

所有位于工作区（AppMain）中的区块（包括 Section、ToolBar 等直接子元素），其 padding 和 margin-bottom 必须严格根据屏幕断点使用以下响应式数值。实际实现通过 CSS 变量 `--app-block-pad` 和 `--app-block-mb` 驱动（定义在 `src/styles/index.scss`），配合 `.app-page` 的 `gap` 属性自动间距，无需 `!important`。

```scss
// 实际实现: CSS 变量驱动 (index.scss)
:root {
  --app-block-pad: 4px;
  --app-block-mb: 4px;
}
@media (min-width: 768px) {
  :root {
    --app-block-pad: 8px;
    --app-block-mb: 8px;
  }
}
@media (min-width: 1024px) {
  :root {
    --app-block-pad: 16px;
    --app-block-mb: 16px;
  }
}
```

**间距对照表：**

| 视口 | 宽度 | padding | margin-bottom |
|------|------|---------|---------------|
| 手机端 (Mobile) | `< 768px` | 4px | 4px |
| 平板端 (Tablet) | `768-1023px` | 8px | 8px |
| 电脑端 (Desktop) | `>= 1024px` | 16px | 16px |

> 不再强制手机端单列化。多 Section 可同行并排（`auto-fit`），用户可保留横向卡片墙。

## 4. 表单 (Form)

系统统一推荐使用"单表单页 (Single Form Page)"结构。该结构规范了典型数据密集型表单页面的纵向流布局。

```
+--------------------------------------------------------------+
|                          标题区 (Title)                      |
+--------------------------------------------------------------+
|                        过滤区 (Filter)                       |
+--------------------------------------------------------------+
|                        工具条 (Toolbar)                      |
+--------------------------------------------------------------+
|                        内容区 (Content)                      |
|  +--------------------------------------------------------+  |
|  | 表头 (Header)                                          |  |
|  +--------------------------------------------------------+  |
|  | 行 1 (Row 1) [ 操作 (Actions) ]                        |  |
|  +--------------------------------------------------------+  |
|  | 行 2 (Row 2) [ 操作 (Actions) ]                        |  |
|  +--------------------------------------------------------+  |
+--------------------------------------------------------------+
|                        分页区 (Pagination)                   |
+--------------------------------------------------------------+
```

### 4.1 核心区域规范

1. **标题区 (Title Area)**：
   - 必须位于最上方。包含页面主标题、当前所处位置的简易面包屑，以及可选的全局返回按钮。
2. **过滤区 (Filter Area)**：
   - 放置搜索输入框、下拉选择器、日期范围选择等过滤条件。
   - 条件过多时（超过 3 个），必须支持"展开/收起"折叠交互，默认仅展示核心的 1~2 个高频搜索项。
3. **工具条 (Toolbar Area)**：
   - 包含操作按钮，如"新增"、"批量删除"、"导出"、"刷新配置"等。
   - 按钮排版应当按照重要程度从左往右排列，高危操作（如"删除"）需靠右或使用醒目的红色警示语。
4. **内容区 (Content Area)**：
   - **表头 (Header)**：表头文字应简明扼要，数值列靠右对齐、文本列靠左对齐、状态/操作列居中对齐。
   - **行 (Row)**：行高必须统一，鼠标悬浮（Hover）时需有整行高亮背景反馈，双击可触发查看详情或编辑。
   - **操作 (Actions)**：单行的行内操作按钮（如编辑、删除、详情），数量超过 3 个时，必须收纳至 `el-dropdown` "更多"下拉菜单中。
5. **分页区 (Pagination Area)**：
   - 必须固定在表单页的最下方。
   - 必须包含：总条数显示、每页条数切换器（PageSizes）、向前/向后翻页快捷键。

## 5. 风格与品牌 (Styles & Brands)

### 5.2 样式 4 个面

样式由 4 个面共同决定，缺一不可。切品牌时所有面跟随。

1. **边距 (padding / spacing)**：容器 / label / item / input / button 各自的 padding 走 EP CSS 变量。切 theme 时 spacing 不变（spacing 不绑主题）。页面块内边距走 `--app-block-pad` 三档响应式（mobile 4 / tablet 8 / desktop 16）。
2. **框线 (border + radius)**：边框颜色走 4 档派生（主 / light / lighter / extra-light），闲置用 extra-light，focus 用 1px 渐变 ring。圆角由当前品牌决定，禁止业务侧硬编码。
3. **阴影 (shadow)**：4 档（sm / md / lg / xl），form 容器通常无 shadow。focus 不加 box-shadow，改 1px 渐变 ring。
4. **高亮 (focus / active / error / success)**：focus = 1px `--brand-primary-gradient` ring（mask trick）；active = 品牌色 12% bg + 600 weight；error / success / warning 色固定，不绑品牌。

## 8. 图标库 (Icon Library)

为确保图标视觉的一致性，实行**自建专属图标库优先**原则。

```
[自建专属矢量图标库] (优先) ---> [Remix Icon] (降级/补位) ---> [Element Plus Icons] (UI组件专用)
```

1. **自建专属矢量图标库 (Iconfont / SVG Component Pack)**：
   - 优先使用设计师统一定制、并封装为 Vue SVG 组件的自建图标。
   - 自建图标需严格保持统一的网格比例（推荐基于 24x24 的画布规范绘制）和一致的描边粗细（通常为 1.5px 或 2px）。
2. **Remix Icon (开源备用库)**：
   - 当自建图标库中缺少所需图标时，**仅允许使用 Remix Icon** (https://remixicon.com/) 作为备选补位库。
   - 引入 Remix Icon 时需按需打包，禁止全量引入。
3. **Element Plus Icons**：
   - 仅在基础 UI 组件内部属性（如 `el-button` 的 `icon` 属性、`el-input` 的 `prefix-icon`）中允许使用，避免滥用到业务菜单和重要可视化看板中。

## 9. 素材库 (Asset Library)

为了统一极简主义的系统美学，任何图片、状态图、占位素材禁止随意从网络下载引入，必须在指定场景下使用以下标准素材：

### 9.1 缺省状态 (No Data / Empty)

- 当页面、表格、卡片无任何数据返回时，必须使用统一的 **SVG 极简无数据缺省插图**。
- 插图整体色调需跟随当前主题的 `--app-text-tertiary` 降低饱和度显示（`currentColor` 方式）。
- 按 brand 提供 `_empty_<brand>.svg`，缺失自动回退 `_empty_default.svg`。
- 通过 `el-empty` 的 `#image` 插槽以 `v-html` 注入 SVG，`description` 走 i18n 文字。

**设计原则：**

1. **颜色单色**：灰轮廓（`currentColor` → `--app-text-tertiary`），不绑主题色也不绑品牌色，让空态"沉"在页面里。
2. **一图通吃**：一个空态 SVG 应对所有场景，通过 `description` 文本区分语义（无数据 / 无记录 / 未找到）。
3. **brand fallback**：`useBrandEmpty` 按 `preference.brand` 选 SVG，缺失回退 `_empty_default.svg`。
4. **无动画**：空态是静态状态指示。

**文件命名约定：**

```
src/assets/empties/
├── _empty_default.svg     # 通用空态 (EP 原 svg: 多页 paper 叠层)
└── _empty_mchuan.svg      # mchuan 品牌专属

# 未来加更多 brand: 复制 _empty_mchuan.svg → _empty_<brand>.svg,
# 改形状/造型. composable 按 preference.brand 自动选, 缺失回退 _empty_default.svg
```

**用法：**

```vue
<script setup>
import { useBrandEmpty } from '@/composables/useBrandEmpty'
const { svg } = useBrandEmpty()  // self-contained <svg> element
</script>

<template>
  <el-empty :description="t('common.empty.no-data')">
    <template #image>
      <div class="brand-empty-svg" v-html="svg" />
    </template>
  </el-empty>
</template>

<style scoped>
.brand-empty-svg { width: 120px; height: 120px; color: var(--app-text-tertiary); }
.brand-empty-svg :deep(svg) { width: 100%; height: 100%; }
</style>
```

### 9.2 默认头像 (Default Avatar)

- 用户未上传头像时的兜底方案。
- 禁止使用具体的人物照片。必须使用统一的**中性几何剪影 SVG 矢量图**，或根据用户昵称首字动态生成的带有随机柔和底色（避开高饱和度红绿色）的字符头像。

### 9.3 加载状态 (Loading / Shimmer)

- **全局/长载入**：基于 Element Plus `v-loading`，按 brand 自动切换 SVG spinner（`src/assets/loadings/_loading_<brand>.svg`）。SVG 内 stroke/fill 用 `currentColor`，顶层 `.el-loading-spinner .circular` 设 `color: var(--el-color-primary)`。缺失文件回退 `_loading_default.svg`。
- **品牌渐变**：个别品牌需要渐变（如 mchuan 蓝→紫），可在 SVG 内硬编码 `stop-color` 与按钮渐变一致。
- **卡片/列表局部载入**：优先采用**骨架屏 (Skeleton / Shimmer Effect)** 动效，骨架横条的圆角和底色必须跟随当前主题。

**文件命名约定：**

```
src/assets/loadings/
├── _loading_default.svg     # 等同 EP 内置 (回退用)
└── _loading_mchuan.svg      # mchuan 品牌 spinner
```

**用法 — 指令式：**

```vue
<script setup>
import { useBrandLoading } from '@/composables/useBrandLoading'
const { svg: loadSvg, svgViewBox } = useBrandLoading()
</script>

<template>
  <div
    v-loading="loading"
    :element-loading-svg="loadSvg"
    :element-loading-svg-view-box="svgViewBox"
    element-loading-text="加载中…"
  >
    ...
  </div>
</template>
```

**用法 — 服务式：**

```typescript
import { brandLoadingService } from '@/composables/useBrandLoading'

const instance = brandLoadingService({
  target: '.my-region',
  text: '加载中…',
  // brand: 'mchuan',  // 可选, 不传走当前 preference.brand
})
// ...异步完成后
instance.close()
```

## 10. 反馈 (Feedback)

### 10.1 通知 (Notification)

基于 Element Plus `ElNotification`，统一规范如下：

**设计原则：**

1. **位置**：默认 `top-right`，不阻塞主操作。不建议 `bottom-right`（易被操作栏遮挡）。
2. **自动关闭**：默认 3000ms 自动关闭，错误类 5000ms 留更多阅读时间。关键操作（支付/删除）用 `duration: 0` 强制手动关闭。
3. **5 种类型**：primary / success / warning / info / error，颜色 token 走 EP `--el-color-{primary,success,warning,info,danger}`，切主题/品牌自动跟随。
4. **视觉壳对齐**：白底 + 1px 边框 + 圆角 + 阴影（同一组 `--el-bg-color / --el-border-color-extra-light / --app-radius-card / --app-shadow-md`），不沿用 EP 默认灰底。

**用法：**

```typescript
import { ElNotification } from 'element-plus'

ElNotification({
  title: '操作成功',
  message: '数据已保存到服务器',
  type: 'success',                  // 'success' | 'warning' | 'info' | 'error' | ''
  position: 'top-right',
  duration: 10000,
  customClass: 'app-notification',  // 走项目主题 CSS, 对齐 WorkSection
  icon: () => h('i', { class: 'ri-checkbox-circle-line app-notification__icon' }),
})
```

### 10.2 弹出框 (Dialog)

使用项目封装的 `AppDialog` 组件，基于 EP `el-dialog` 扩展。

**设计原则：**

1. **可拖动**：头部区域可拖动，鼠标变 `move` 光标。
2. **背景高斯模糊**：遮罩层 backdrop-filter 模糊背景，突出弹窗。
3. **视觉壳对齐**：与 WorkSection 共享同一组 CSS 变量，确保视觉一致。
4. **可调大小**：右下角 12px 斜线手柄，移动端 44px 触摸区。

**用法：**

```vue
<script setup>
import AppDialog from '@/components/sdk/common/AppDialog.vue'

</script>

<template>
  <AppDialog
    v-model:visible="show"
    title="编辑资料"

    @resize="(w, h) => console.log('resized', w, h)"
  >
    <p>内容...</p>
    <template #footer>
      <el-button @click="show = false">取消</el-button>
      <el-button type="primary" @click="show = false">确认</el-button>
    </template>

</template>
```

### 10.3 抽屉 (Drawer)

使用项目封装的 `AppDrawer` 组件，基于 EP `el-drawer` 扩展。

**设计原则：**

1. **默认右侧滑出**：`direction="rtl"`，与侧边栏方向一致。
2. **背景高斯模糊**：与 Dialog 同策略。
3. **视觉壳对齐**：与 WorkSection 共享同一组 CSS 变量。
4. **可调大小**：左侧 1px 拖拽条（EP 内置）。

**用法：**

## 11. 检查单与开发规范自测 (Self-Check Checklist)

在每次提交 Pull Request 或上线前，开发人员必须对照下表进行自检：

- [ ] **路由检查**：路由配置文件中，所有的 router 实例是否已明确声明 `history: createWebHistory()`？
