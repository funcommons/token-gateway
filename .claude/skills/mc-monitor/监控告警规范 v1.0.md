## 1. 概述

### 1.1 可观测三支柱

| 支柱 | 回答的问题 | 工具 |
|---|---|---|
| **Metrics**（指标） | 发生了什么（聚合数值） | Prometheus + Micrometer |
| **Tracing**（追踪） | 在哪儿发生（跨服务链路） | OpenTelemetry + Tempo |
| **Logging**（日志） | 具体内容（详情） | Loki / ELK + LogstashEncoder |

**统一**：trace_id 贯穿三支柱（MDC + W3C TraceContext）。

### 1.2 黄金信号

**RED（服务）**：Rate / Errors / Duration

**USE（资源）**：Utilization / Saturation / Errors

**LET（业务）**：Latency / Errors / Traffic

### 1.3 监控成熟度

| 级 | 特征 |
|---|---|
| L0 | 无监控 |
| L1 | 基础监控（CPU / 内存） |
| L2 | 应用监控（JVM / DB / HTTP） |
| L3 | 业务监控（订单数 / GMV / 错误率） |
| L4 | SLO + 错误预算驱动开发 |
| L5 | 自愈 + 智能告警 |

### 2.1 Spring Boot 接入

```xml

</dependency>
<dependency>
    <groupId>io.micrometer</groupId>

```

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health, info, prometheus, metrics
  metrics:
    tags:
      application: order-service
      env: ${spring.profiles.active}
    distribution:
      percentiles-histogram:
        http.server.requests: true
      percentiles:
        http.server.requests: 0.5, 0.95, 0.99
```

访问 `/actuator/prometheus` 获取文本格式指标。

### 2.2 Micrometer API

**Counter**（单调递增）：

```java
@Autowired MeterRegistry registry;

Counter ordersCreated = Counter.builder("orders_created_total")
    .tag("type", "default")
    .tag("channel", "web")
    .description("订单创建总数")
    .register(registry);

ordersCreated.increment();
ordersCreated.increment(2);
```

**Gauge**（瞬时值，可升降）：

```java
Gauge.builder("users_online", userService, UserService::countOnline)
    .register(registry);

// 注意：Gauge 的引用必须强可达，否则 GC 后值变 0
```

**Timer**（耗时分布）：

```java
Timer timer = Timer.builder("orders_process_duration")
    .publishPercentiles(0.5, 0.95, 0.99)
    .publishPercentileHistogram()
    .register(registry);

timer.record(() -> processOrder());

// 或注解
@Timed(value = "orders_create_duration",
       percentiles = {0.5, 0.95, 0.99},
       histogram = true)
public String create(...) { ... }
```

**DistributionSummary**（任意数值分布）：

```java
DistributionSummary summary = DistributionSummary.builder("order_amount")
    .baseUnit("yuan")
    .register(registry);

summary.record(order.getTotalAmount().doubleValue());
```

**LongTaskTimer**（长任务监控）：

```java
LongTaskTimer longTimer = LongTaskTimer.builder("exports_running").register(registry);
LongTaskTimer.Sample sample = longTimer.start();
try { /* 长任务 */ } finally { sample.stop(); }
```

### 2.3 标签设计

| 原则 | 示例 |
|---|---|
| 低基数（≤ 10 值） | `type=default/vip/wholesale` |
| 禁用高基数 | ❌ `user_id=12345` / `order_id=xxx` |
| 业务维度 | `payment_method=wechat/alipay/card` |
| 环境维度 | `env=dev/staging/prod` |

**Prometheus 单实例最多 200 个时序/服务**。`tag * value` 组合 = 时序数。

### 4.2 自动埋点覆盖

OTel auto-instrumentation 自动捕获：

- HTTP 入口（Spring MVC）
- HTTP 出口（RestTemplate / WebClient / OkHttpClient）
- DB（JDBC / MyBatis / HikariCP）
- 缓存（Lettuce / Jedis / Redisson）
- 消息队列（Kafka / RocketMQ / RabbitMQ）
- RPC（gRPC / Dubbo）
- 异步（@Async / @Scheduled）

### 4.3 手动埋点

```java
import io.opentelemetry.api.GlobalOpenTelemetry;
import io.opentelemetry.api.trace.Tracer;
import io.opentelemetry.api.trace.Span;
import io.opentelemetry.api.trace.StatusCode;
import io.opentelemetry.context.Scope;

@Service
public class OrderService {
    private static final Tracer TRACER = GlobalOpenTelemetry.getTracer("order-service");

    public String create(OrderCreateRequest req) {
        Span span = TRACER.spanBuilder("order.create.business")
            .setAttribute("order.sku", req.getSku())
            .setAttribute("order.quantity", req.getQuantity())
            .setAttribute("user.id", SecurityContext.current().getId())
            .startSpan();

        try (Scope scope = span.makeCurrent()) {
            span.addEvent("validation.start");
            validate(req);
            span.addEvent("validation.end");

            span.addEvent("db.insert.start");
            orderMapper.insert(order);
            span.addEvent("db.insert.end");

            return order.getId().toString();
        } catch (Exception e) {
            span.recordException(e);
            span.setStatus(StatusCode.ERROR, e.getMessage());
            throw e;
        } finally {
            span.end();
        }
    }
}
```

### 4.5 Tempo TraceQL

```
# 错误 trace
{ status = error }

# 慢 trace（> 1s）
{ duration > 1s }

# 指定服务
{ service.name = "order-service" }

# 指定属性
{ span.order.sku = "SKU001" }

# 复合查询
{ service.name = "order-service" && status = error && duration > 500ms }
```

### 4.6 采样策略

| 类型 | 适用 | 配置 |
|---|---|---|
| **Probabilistic**（概率） | 通用，10-30% | `probability: 0.1` |
| **AlwaysOn** | 开发环境 | `probability: 1.0` |
| **AlwaysOff** | 关闭 | `probability: 0` |
| **Tail-based**（链尾） | 错误全采、慢全采 | OTel Collector 配 |

**Collector tail sampling**：

```yaml
processors:
  tail_sampling:
    decision_wait: 10s
    policies:
      - name: errors
        type: status_code
        status_code: { status_codes: [ERROR] }
      - name: slow
        type: latency
        latency: { threshold_ms: 1000 }
      - name: random
        type: probabilistic
        probabilistic: { sampling_percentage: 10 }
```

## 6. Alerting（Alertmanager）

### 6.1 告警分级

| 级别 | 触发 | 通知 | 响应 |
|---|---|---|---|
| P0 | 核心不可用 / 资金异常 / 数据丢失 | 电话 + 短信 + 钉钉 | 5 分钟 |
| P1 | 错误率 > 1% / P99 翻倍 / CPU > 80% | 钉钉 | 30 分钟 |
| P2 | 磁盘 > 80% / 连接池 > 70% | Slack | 2 小时 |
| P3 | 业务波动 | 邮件 | 工作日 |

### 6.2 Prometheus Alert Rules

```yaml
groups:
  - name: order-service
    interval: 30s
    rules:
      # P0
      - alert: OrderServiceDown
        expr: up{job="order-service"} == 0
        for: 1m
        labels: { severity: P0, team: order }
        annotations:
          summary: "Order service down"
          description: "{{ $labels.instance }} down for 1min"
          runbook: "https://wiki/runbook/order-service-down"

      - alert: OrderServiceHighErrorRate
        expr: |
          sum(rate(http_server_requests_seconds_count{job="order-service",status=~"5.."}[5m]))
          /
          sum(rate(http_server_requests_seconds_count{job="order-service"}[5m]))
          > 0.05
        for: 2m
        labels: { severity: P0, team: order }
        annotations:
          summary: "Error rate > 5%"
          description: "Current: {{ $value | humanizePercentage }}"

      # P1
      - alert: OrderServiceHighLatency
        expr: |
          histogram_quantile(0.99, rate(http_server_requests_seconds_bucket{job="order-service"}[5m])) > 1
        for: 5m
        labels: { severity: P1 }
        annotations:
          summary: "P99 > 1s"

      - alert: HighCPU
        expr: rate(process_cpu_usage{job="order-service"}[1m]) > 0.8
        for: 5m
        labels: { severity: P1 }
        annotations:
          summary: "CPU > 80%"

      # P2
      - alert: HighDisk
        expr: 100 - (node_filesystem_avail_bytes * 100 / node_filesystem_size_bytes) > 80
        for: 10m
        labels: { severity: P2 }
        annotations:
          summary: "Disk > 80%"

      # JVM
      - alert: JVMHeapHigh
        expr: jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"} > 0.85
        for: 5m
        labels: { severity: P1 }
        annotations:
          summary: "JVM heap > 85%"

      - alert: JVMGcPauseHigh
        expr: rate(jvm_gc_pause_seconds_sum[1m]) > 0.5
        for: 2m
        labels: { severity: P1 }
        annotations:
          summary: "GC time > 50%"
```

### 6.3 Alertmanager 配置

```yaml
global:
  resolve_timeout: 5m

route:
  receiver: default
  group_by: ['alertname', 'service']
  group_wait: 30s
  group_interval: 5m
  repeat_interval: 4h
  routes:
    - matchers: [severity = P0]
      receiver: dingtalk-p0
      group_wait: 0s
      repeat_interval: 1h
    - matchers: [severity = P1]
      receiver: dingtalk-p1
    - matchers: [severity = P2]
      receiver: slack-p2

receivers:
  - name: default
    webhook_configs:
      - url: 'https://slack.com/...'

  - name: dingtalk-p0
    webhook_configs:
      - url: 'https://oapi.dingtalk.com/robot/send?access_token=p0-token'
        send_resolved: true

  - name: dingtalk-p1
    webhook_configs:
      - url: 'https://oapi.dingtalk.com/robot/send?access_token=p1-token'

inhibit_rules:
  # 同服务 P0 触发时抑制 P1/P2
  - source_matchers: [severity = P0]
    target_matchers: [severity =~ "P1|P2"]
    equal: ['service']
```

### 6.4 钉钉 webhook（自定义）

```python
# alertmanager-dingtalk-adapter.py
from flask import Flask, request
import requests

app = Flask(__name__)

@app.route('/dingtalk', methods=['POST'])
def forward():
    alerts = request.json['alerts']
    for a in alerts:
        status = a['status']
        summary = a['annotations'].get('summary', 'No summary')
        msg = f"**[{status}] {a['labels']['alertname']}**\n{summary}\nRunbook: {a['annotations'].get('runbook', '')}"

        requests.post(
            'https://oapi.dingtalk.com/robot/send?access_token=xxx',
            json={
                'msgtype': 'markdown',
                'markdown': {'title': 'Alert', 'text': msg}
            }
        )
    return 'OK'
```

或用现成的 [prometheus-webhook-dingtalk](https://github.com/timonwong/prometheus-webhook-dingtalk)。

### 6.5 告警治理

| 反模式 | 解决 |
|---|---|
| 告警风暴 | 分组 + 抑制 + repeat_interval |
| 模糊告警 | summary 简短，description 详细 |
| 无 Runbook | 强制 annotations.runbook |
| 噪音告警 | 调阈值 + for 持续时间 |
| 无人响应 | 升级机制（P1 → 30min 无确认 → P0） |

## 8. SLO 错误预算

### 8.1 SLI 公式

```promql
# 可用性 SLI = 1 - 错误率
1 - (
  sum(rate(http_requests_total{job="order-service",code=~"5.."}[28d]))
  /
  sum(rate(http_requests_total{job="order-service"}[28d]))
)

# 延迟 SLI = 慢请求占比的反
1 - (
  sum(rate(http_request_duration_seconds_bucket{job="order-service",le="0.5"}[28d]))
  /
  sum(rate(http_request_duration_seconds_count[28d]))
)
```

### 8.2 SLO 配置

```yaml
slo:
  service: order-service
  window: 28d
  targets:
    availability:
      sli_expr: "..."
      target: 0.999                    # 99.9%
    latency_p99:
      sli_expr: "..."
      target: 0.99                     # 99% 请求 < 500ms
      threshold: 500ms
```

### 8.3 错误预算计算

```
可用性 99.9% → 30 天允许错误 30 * 24 * 60 * 0.001 = 43.2 分钟
错误预算 = 总请求 * (1 - SLO)
```

### 8.4 燃烧率告警

```yaml
# 1 小时烧 2% 预算 → 立即告警（P1）
- alert: SLOBurnRateHigh
  expr: |
    (
      sum(rate(http_requests_total{job="order-service",code=~"5.."}[1h]))
      /
      sum(rate(http_requests_total{job="order-service"}[1h]))
    )
    / (1 - 0.999) > 14.4
  and
    ...同表达式 but [5m]...
  for: 2m
  labels: { severity: P1 }
  annotations:
    summary: "SLO burn rate high (2% in 1h)"

# 6 小时烧 5% 预算 → P2（慢速告警）
- alert: SLOBurnRateSlow
  expr: |
    (...[6h]...) / (1 - 0.999) > 6
  for: 15m
  labels: { severity: P2 }
```

### 8.5 错误预算 Dashboard

```
Panel 1: 剩余预算（百分比）
Panel 2: 预算燃烧速率（条形）
Panel 3: SLI 趋势（线图）
Panel 4: 当月错误事件列表
```

### 8.6 错误预算驱动开发

| 状态 | 行动 |
|---|---|
| 预算剩余 > 50% | 推进新功能 / 容错性变更 |
| 预算剩余 20-50% | 谨慎上线 |
| 预算剩余 < 20% | 暂停新功能，优先稳定性 |
| 预算耗尽 | 冻结非紧急上线，全力修复 |

## 9. 业务事件埋点

### 9.1 原则

- **少而精**：每个指标都要进 Dashboard 和告警
- **标签低基数**：≤ 10 个值
- **事件 + 计数分离**：Counter 用于累计，Gauge 用于瞬时

### 9.2 推荐埋点

| 业务 | 指标 | 类型 |
|---|---|---|
| 订单创建 | `orders_created_total{type, channel}` | Counter |
| 订单完成 | `orders_completed_total` | Counter |
| 订单金额分布 | `order_amount_distribution` | Summary |
| 在线用户数 | `users_online` | Gauge |
| 待处理订单 | `orders_pending_count` | Gauge |
| 库存预警 | `inventory_low_alert{sku}` | Counter |
| 支付失败 | `payments_failed_total{reason}` | Counter |
| 任务积压 | `jobs_pending_count{queue}` | Gauge |
| Kafka lag | `kafka_consumer_lag{topic}` | Gauge |

### 9.3 事件埋点

```java
@EventListener
public void onOrderCreated(OrderCreatedEvent event) {
    meterRegistry.counter("orders_created_total",
        "type", event.getType(),
        "channel", event.getChannel()
    ).increment();

    meterRegistry.summary("order_amount_distribution")
        .record(event.getAmount().doubleValue());

    log.info("Order created")
        .addKeyValue("order_id", event.getOrderId())
        .addKeyValue("user_id", event.getUserId())
        .addKeyValue("amount", event.getAmount())
        .log();
}
```
