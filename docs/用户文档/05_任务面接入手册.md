## 1. 任务面定位

- 部署分组 `face: task | all`（挂资源缓存盘，独立扩缩）；与 LLM 面共用凭证/计费/审核/日志/审计基建。
- **控制层决策**：key 验证与路由表由控制层决定（token-validate / route 能力面），网关数据面执行；计费顺序 = 先路由定价（模型不同价格不同），再全额预扣。
- 两种形态：**lotask4j 托管**（默认——任务表/状态机/重试/僵尸回收平台托管，自写 Worker 经 Groovy 脚本执行"哑"上游）与
  **委托面**（后端自持任务状态，实现 `task/create` + `task/poll` 能力面，见后端接入手册 §4.8）。
- 资源代理与 notify 为网关固有：**上游原始 URL 永不透传**，代理 URL 携带 24h 有效 exp+sig 能力凭证。

## 2. 端点总览（任务面）

| # | 端点 | Method | 说明 |
|---|---|---|---|
| 1 | `/v1/onetoken/videos` · `/v1/onetoken/images` · `/v1/onetoken/audios` · `/v1/onetoken/tts` | POST | 创建任务（四模态同构） |
| 2 | `/v1/onetoken/videos/{task_no}`（四模态同构） | GET | 轮询任务状态 |
| 3 | `/v1/onetoken/images/sync` | POST | 同步生图封装（OpenAI 形状，见 §3.5） |
| 4 | `/v1/resources/{task_no}/{index}?exp=&sig=`（或 `/{index}.{ext}` 双形态） | GET | 资源代理（免凭证，sig 能力凭证；按上游自动判 Content-Type，浏览器内联渲染） |

> 注意：任务面端点自 v0.8.0 起挂 `/v1/onetoken/*`（issue #20，与 OpenAI 官方端点解耦）；`/v1/onetoken/images`（异步任务）、`/v1/onetoken/images/sync`（同步生图封装）与 LLM 面 `/v1/images/generations`（同步生图透传）是三个端点，勿混。

## 3. 调用流程（四段式，以视频为例）

```bash
# ① 创建（同步返回 task_no：控制层 key 验证 → 路由表 resolve 定价 → 按命中模型全额预扣；
#    余额不足 10617 且不产生任务）
curl -s http://localhost:9401/v1/onetoken/videos \
  -H "Authorization: Bearer <凭证>" -H "Content-Type: application/json" \
  -d '{"model":"vid-1.5","params":{"duration":5,"resolution":"720p"},"notify_url":"https://you/callback"}'
# → {"task_no":"T20260831...","status":"PENDING","poll_url":"/v1/onetoken/videos/T20260831..."}

# ② 轮询（调用方 3~5s 驱动；终态幂等，重复轮询不触上游、不重复退款）
curl -s http://localhost:9401/v1/onetoken/videos/T20260831... -H "Authorization: Bearer <凭证>"
# → {"status":"SUCCEEDED","result":{"resources":["<代理URL>"],"usage":{...}}}
#    轮询/创建遇 504+10003 = 凭证校验服务瞬时不可用（可重试基础设施错误），
#    退避重试即可，勿按 key 失效判死任务（401+10202 才是）。

# ③ 资源获取（result.resources 是网关代理 URL，携带 24h 有效 exp+sig，浏览器/下载端免凭证直取）
curl -sL "<代理URL>" -o out.mp4
```

### 3.5 同步生图封装（`POST /v1/onetoken/images/sync`，OpenAI 形状）

OpenAI Images 协议形状的**同步**生图入口：网关内部走「创建图像任务 + 轮询至终态」，调用方一次请求拿到结果。给只想用 OpenAI 形状、不想管理任务轮询的接入方使用。

```bash
curl -s http://localhost:9401/v1/onetoken/images/sync \
  -H "Authorization: Bearer <凭证>" -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2","prompt":"一只戴墨镜的猫","size":"1024x1024"}'
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model` / `prompt` | string | 是 | 模型名 / 提示词（路由定价依据） |
| `size` | string | 否 | 原生透传（gpt-image 系三档 / auto） |
| `ratio` / `resolution` | — | 否 | 扩展参数透传（如 9:16） |
| `n` | int | 否 | **仅支持 1**（任务面单图语义；>1 → 400） |

三种出口（按响应体分流）：

| 情形 | HTTP | 响应 |
|---|---|---|
| 终态成功（同步窗内，默认 60s） | 200 | `{created, data:[{url}]}`——OpenAI images 响应形状；`url` 为网关签名代理 URL（24h） |
| 上游失败 / EXPIRED | 502 | 错误信封（10004 语义），`message` 为上游错误；已自动全额退款 |
| 同步窗超时未终态 | 200 | `{status:"PROCESSING", task_no, poll_url}`——降级为异步：按 `poll_url`（`/v1/onetoken/images/{task_no}`）继续轮询（§3 ②同款） |

计费与幂等同 §4 语义（本质是图像任务：创建即全额预扣，失败/超时退款）；支持 `Idempotency-Key`（见[通用约定 §6](./03_通用约定.md)）。

> 与另外两个成图端点的区分：LLM 面 `/v1/images/generations` 是**透传**型同步生图（上游须同步支持）；本端点是网关**任务引擎**的同步封装（上游只要是任务面可接的生图模型即可）。OpenAI 官方 `background:true` 异步模式暂不支持透传轮询（见 issue #19）。

## 4. 语义要点

| 事项 | 语义 |
|---|---|
| 计费 | 先路由定价（按 resolve 命中的模型计价），创建即**全额预扣**；FAILED / EXPIRED 自动**全额退款**；SUCCEEDED 不退（预扣即支付），无 usage 结算步 |
| 状态机 | `PENDING → RUNNING → SUCCEEDED / FAILED / EXPIRED`；超 24h（可按模态配置）未终态 → EXPIRED + 全额退款 |
| 轮询 | 终态后幂等返回存储结果（不触上游、不重复退款）；查询异常状态不变，退避重试即可 |
| notify | 创建带 `notify_url` 时终态回调，`X-THMP-Signature`（HMAC）可验签；失败由网关退避重发（1m/10m/1h 档位），调用方无需兜底 |
| 资源代理 | **上游原始 URL 永不透传**；代理 URL 24h 过期（exp+sig），过期重取任务可再签；签名过期/篡改 → 10100，任务非 SUCCEEDED → 10402。支持 `/{index}.{ext}` 后缀双形态（验签与无后缀等价，便于浏览器/IM 内联渲染）；上游回内联 `data:...;base64` 时自动解码转存，调用方拿到的仍是代理 URL |
| 审核开关 | 任务面与 LLM 面共用 `moderation.enabled` 配置 |
| 幂等 | 创建端点支持 `Idempotency-Key`（见[通用约定 §6](./03_通用约定.md)） |

## 5. notify 回调验签

创建时携带 `notify_url` 的任务，终态后网关回调：

```http
POST <notify_url>
Content-Type: application/json
X-THMP-Signature: Base64(HmacSHA256(notify_sign_key, rawBody))

{"task_no":"T...","status":"SUCCEEDED","result":{"resources":["<代理URL>"],"usage":{...}}}
```

- 验签密钥由平台方发放（对应网关 `task.notify-sign-key`）；先退款后回调，收到 FAILED 时退款已到账。
- 回调失败网关按 1m/10m/1h 退避重发；回调方请按 `task_no` 幂等处理（重复投递可能）。

## 6. 接入验收清单（任务面）

- [ ] create 带 `Idempotency-Key`；余额不足 10617 时不展示为"任务创建中"
- [ ] 轮询 3~5s 节拍；终态后停止轮询（幂等返回存储结果）
- [ ] 资源一律走代理 URL 获取；不假设代理 URL 永久有效（24h，过期重取任务再签）
- [ ] notify 接收端验签 + 按 task_no 幂等；notify 与轮询至少可靠走通一路
- [ ] 错误处理覆盖 10400（任务不存在）/ 10402（未成功取资源）/ 10100（签名过期）

## 7. 网关侧任务配置（face=task/all 时生效）

```yaml
token-gateway:
  face: task
  task:
    expire-scan: 24h                     # 任务过期窗口（超时 EXPIRED + 全额退款）
    resource-cache-dir: /data/tgw-cache  # 资源代理缓存目录（face=task 实例挂盘）
    resource-sign-key: ${TGW_RESOURCE_SIGN_KEY}
    notify-sign-key: ${TGW_NOTIFY_SIGN_KEY}      # notify 回调 X-THMP-Signature 签名密钥
    notify-retry: 1m,10m,1h              # notify 重发退避档位
    snapshot-cipher-key: ${TGW_SNAPSHOT_CIPHER_KEY}  # 路由快照 AES-GCM（出站凭证不明文落平台库）
    lotask:                              # lotask4j 平台（任务状态托管，V4+）
      url: ${LOTASK_URL}
      auth: jwt                          # jwt 推荐 / key 内网限定 / none 仅 localhost
      jwt-secret: ${LOTASK_JWT_SECRET}
      access-key: ${LOTASK_ACCESS_KEY}   # 写操作 HMAC 四头
      sign-key: ${LOTASK_SIGN_KEY}
      tenant-secret: ${LOTASK_TENANT_SECRET}     # webhook 验签（reset-secret 轮换配 tenant-secret-previous）
      webhook-callback-url: ${LOTASK_WEBHOOK_CALLBACK_URL}  # 网关 /internal/lotask/webhook 公网地址
    submit-task-type: modality           # 任务派发粒度: modality(默认,零感知) | model
                                         # model = 任务按请求体 model 编码派发给 Worker
                                         # (Worker 脚本以 modelCode 拉单时须配, 否则任务无人
                                         #  认领持续 PENDING; 切换后 timeouts 须按模型编码建键)
    timeouts:                            # 超时钟按 task_type 覆盖默认窗口 (键粒度随 submit-task-type)
      video: 2h
      image: 30m
```

调度兜底：超时钟（deadline 到期反查终态 → EXPIRED + 退款）与预扣-终态对账由网关自持
（TimeoutClockJob / ReconcileJob）；任务状态机/重试/僵尸回收由 lotask4j 平台托管。
