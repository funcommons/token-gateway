# 通用约定

本文是**所有调用方必读**的横切规范：认证、响应形态、错误码、错误形状切换、限流、幂等、链路追踪、超时预算。LLM 面与任务面完全一致。

## 1. 认证

| 方式 | Header | 说明 |
|---|---|---|
| Bearer（推荐） | `Authorization: Bearer <凭证>` | OpenAI 生态默认 |
| API-Key 头 | `x-api-key: <凭证>` | Anthropic 生态默认；两头同发以 Bearer 优先 |

- 凭证校验在管线第一步，失败返回 **10202 令牌无效 / 10200 未认证**（HTTP 401 + 错误信封）。
- 凭证校验服务自身瞬时不可用（基础设施抖动/超时）返回 **10003**（HTTP 504）——这是可重试错误，**不代表凭证有问题**，退避重试即可，勿按凭证失效处理。
- 凭证向哪个后端校验由模型路由决定——**换后端不换调用方式**。
- 凭证不会出现在任何网关日志与错误信息中。

## 2. 响应形态（成败判定铁律）

| 形态 | HTTP | Body | 判定 |
|---|---|---|---|
| 成功（LLM 非流式） | 200 | 上游业务形状（OpenAI/Anthropic），**无信封** | 有 `choices`/`content`/`data` 即成功 |
| 成功（LLM 流式） | 200 | `text/event-stream` | 逐段解析，`[DONE]`/`message_stop` 结束 |
| 成功（任务面） | 200 | `{task_no, status, ...}` 业务形状 | 有 `task_no` 即成功 |
| 业务/系统错误 | 4xx/5xx | 6 字段错误信封 | `code != 0` 即失败 |

错误信封（6 字段）：

```json
{
  "code": 10202,
  "message": "令牌无效",
  "data": null,
  "error": [{"field": null, "code": null, "message": "令牌无效", "value": null}],
  "trace_id": "c0a80101-...",
  "timestamp": 1756600000000
}
```

> **注意**：不要用 HTTP status 之外的启发式判失败，也不要假设成功响应带 `code` 字段——成功是透传形状。

## 3. 错误码速查

| code | HTTP | 含义 | 调用方处置 |
|---|---|---|---|
| 10001 | 500 | 系统繁忙 | 退避重试 |
| 10003 | 504 | 服务调用超时 / 凭证校验服务暂不可用 | 退避重试；长文本检查 max_tokens |
| 10004 | 502 | 第三方服务异常（上游全失败 / 任务平台不可用） | 退避重试；持续失败联系平台 |
| 10100~10106 | 400 | 参数错误/缺失/格式/范围/JSON；10106 亦用于内容安全拒绝；资源代理签名过期/篡改回 10100 | 修请求，勿重试 |
| 10200 | 401 | 未认证/令牌过期 | 换有效凭证 |
| 10202 | 401 | 令牌无效 | 换有效凭证 |
| 10300 | 403 | 权限不足（模型未开通） | 联系平台开通 |
| 10400 | 404 | 模型不存在/无可用渠道；任务不存在 | 核对 model / task_no |
| 10402 | 409 | 状态冲突（如任务非 SUCCEEDED 取资源） | 按业务处理 |
| 10500 | 429 | 请求过频 | 按 `Retry-After` 退避 |
| 10501 | 409 | 重复提交（幂等 key 命中：处理中或不可回放） | 原样重试等待回放；或换新 Idempotency-Key |
| 10617 | 402 | 余额不足 | 充值后重试；任务面不产生任务 |
| 10700 | 200 | 部分成功 | 按 `data` 内明细处理 |

> 上游渠道返回 4xx/5xx 时，网关如实透传上游 HTTP 状态与信封业务码（如 401→10202、429→10500、5xx→10001/10004），错误消息带 `upstream error HTTP_<status>` 前缀——据此可与调用方自身凭证问题区分（消息体而非 502 一刀切）。

## 4. 错误形状切换（`gateway.error-shape`）

网关错误响应支持两种形状，由网关侧配置 `gateway.error-shape` 切换：

| 取值 | 形状 | 说明 |
|---|---|---|
| `envelope`（默认） | 本文档 §2 的 6 字段信封 | 既定公开契约，存量接入方无感 |
| `openai` | OpenAI `{"error":{message,type,param,code}}` 形状 + 顶层 `trace_id` | OpenAI SDK 可直接解析 |

`openai` 形状的线上样例（HTTP 401）：

```json
{"error":{"message":"令牌无效","type":"authentication_error","param":null,"code":"10202"},"trace_id":"c0a80101-..."}
```

字段承载：

- `error.message` = 信封 `message` 原样透传，不加前后缀。
- `error.type` 按 HTTP 状态映射：

| HTTP 状态 | `error.type` |
|---|---|
| 401 | `authentication_error` |
| 402 | `insufficient_quota` |
| 403 | `permission_error` |
| 404 | `not_found_error` |
| 429 | `rate_limit_error` |
| 5xx | `api_error` |
| 其余 4xx（含 400） | `invalid_request_error` |

- `error.code` = 网关业务码**字符串**（白名单透传场景 = 能力面原码，如 `"4090"`）。OpenAI 原生语义的 code 字符串（`invalid_api_key` / `model_not_found` / `insufficient_quota`）**不单列**——其语义由 `error.type` 一一承载（对照见上表），OpenAI SDK 以 HTTP 状态 + `error.type` 判别错误类别，`error.code` 本就是自由字符串字段，放网关业务码同时满足 SDK 可解析与网关码表不丢（完整错误码表见 [04_LLM面接入手册 §7](./04_LLM面接入手册.md)）。
- `error.param` 恒 `null`（保留 OpenAI 线格式惯例键位）。
- 顶层 `trace_id` 与响应头 `X-Trace-Id` 同源（§5 链路追踪）。

**作用范围**：仅 LLM 面 `/v1/chat`、`/v1/messages` 前缀（含 `/v1/messages/count_tokens`）的**错误**响应；任务面 / 内部端点恒为信封，开关不误伤。成功响应两种配置下都是上游透传形状（§2），不受影响。

> ⚠️ **Breaking 警告**：6 字段信封是既定公开契约。`error-shape=openai` 前必须与**所有存量接入方**对齐——未对齐即切换对存量接入方是 breaking（它们解析不到 `code` 字段）。

### 4.1 能力面业务码透传白名单（`gateway.error-passthrough-codes`）

LLM 面路由（distribute）与预扣（preConsume）失败时，能力面原码命中白名单 → 客户端**直收原码** + 语义 HTTP 状态（**两种错误形状均生效**，与 `error-shape` 无关）：

| 能力面原码 | 透传 HTTP 状态 | 语义 |
|---|---|---|
| 4090 | 403 | 风控拒绝 |
| 10601 | 402 | 余额不足（能力面口径） |
| 10602 | 404 | 模型不存在（能力面口径） |
| 10603 | 404 | — |
| 10402 | 409 | 状态冲突 |

- **白名单优先**：命中即短路返回，不再走既有映射。
- **未命中**走既有映射：10400·20103→404 / 10617→402 / 其余 502+10004。
- 白名单之外的能力面原码**不进网关公开错误码空间**（仅 message 文本残存）。
- 配置与默认白名单**按键合并、同键覆盖**（默认键不可经配置删除，需要收窄只能覆盖同键值）。

## 5. 链路追踪

- 请求可带 `X-Trace-Id`（不传网关生成）；响应头**必回** `X-Trace-Id`。
- 排障时提供 `trace_id` 即可贯通网关日志 ↔ 后端日志 ↔ 访问日志。

## 6. 限流

- 维度：按凭证（apiKey）+ 全局两层；固定窗口。
- 超限：**HTTP 429** + 信封（10500）+ 响应头：

| Header | 含义 |
|---|---|
| `Retry-After` | 建议等待秒数（客户端应指数退避） |
| `X-RateLimit-Limit` | 窗口配额 |
| `X-RateLimit-Remaining` | 剩余额度 |
| `X-RateLimit-Reset` | 重置等待秒数 |

## 7. 幂等（回放语义）

- 写操作（全部 POST `/v1/**`）可带 `Idempotency-Key: <uuid v4>`。作用域 = 凭证 + key，窗口 = TTL（默认 48h）。
- **回放语义**（超时恢复的标准姿势）：
  - 首次请求成功（HTTP 2xx、非流式、响应体 ≤ 1MB）→ 网关缓存首响；TTL 内同凭证同 key 重发 → **原样回放首响**（同状态码 / 同 Content-Type / 同 body），响应头带 **`Idempotency-Replayed: true`**——不重复计费、不重复建任务，接入方按首响业务语义直接消费即可。
  - 首次请求仍在处理中，或首响为流式 / 超限不可缓存 → **409 + 10501**（message 标明「请求处理中」）——稍候重试，首响落缓存后即转为回放。
  - 首次请求失败（非 2xx 或内部异常）→ 占位**立即释放**（失败不占键），同 key 重发**按新请求**执行。
  - 流式响应（`text/event-stream`）与超过 1MB 的响应**不支持回放**：占位在 TTL 内保留，同 key 重发得 409 + 10501——流式调用方请勿依赖幂等回放，超时后按业务侧对账。
- **键值不进入下游参数**：幂等键只用于去重与回放，不会被映射为任何下游业务参数位（如任务面 workId、billing requestId）；billing 侧 requestId 仅接受纯数字，非数字键由网关自动生成纯数字请求 ID。
- 建议：所有非幂等安全的调用（图片生成、任务创建等）必带；收到 10501 时看 message——「请求处理中」→ 稍后原样重试等待回放，其余 → 换新 key。

## 8. 超时预算

| 环节 | 预算 |
|---|---|
| 连接上游 | 3s |
| 首字节 | 30s |
| 总时长 | 300s（SSE 长连接同预算） |
| 网关→后端能力调用 | route 3s / billing 5s / moderation 2s（缺省，注册配置可调） |

超时返回 10003（服务调用超时）信封；上游全失败返回 10004。任务面长耗时不在此预算内——任务异步执行，以轮询/回调为准。
