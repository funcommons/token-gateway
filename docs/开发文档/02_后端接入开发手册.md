# 通用 LLM 网关（token-gateway）后端接入开发手册

| 项 | 内容 |
|---|---|
| 文档 | 后端接入开发手册（把你的系统接入为网关的能力面服务） |
| 受众 | 后端开发者，**语言不限**（Go / Python / Node / Java 均可） |
| 配套 | 能力面契约 `03_能力面接口契约.yaml`（本目录）；设计方案 `01_设计方案.md`（本目录）；调用方文档见 `../用户文档/` |
| 版本 | V1.0（2026-08-31） |

---

## 1. 你在接什么

```
调用方 ──▶ token-gateway ──按能力面调用──▶ 你的后端（本文读者）
                        （网关是客户端，你是服务端）
```

- 网关按**七类能力面**调用后端：凭证校验 / 路由分发 / 计费 / 内容审核 / 访问日志 / 审计 / 模型目录。
- 你**按需实现子集**：只实现你声明启用的能力面，其余面在网关 yml 里关闭或指向别的服务。
- 接入方式 = 实现 《能力面接口契约》的 HTTP 端点（或按 §5 消费日志 MQ），**不写任何网关侧代码、不限语言**。

## 2. 接入模型：选择你的能力面子集

| 你想要 | 必须实现 | 网关侧配置 |
|---|---|---|
| 最小接入（代理 + 你自管计费） | token-validate + route + models | `billing: passthrough` |
| 网关 saga 计费 | 上述 + billing 三端点 | `billing: direct` |
| 内容审核 | moderation/scan | `moderation.enabled: true` |
| 日志归集 | access-log/record **或** 消费日志 MQ | `access-log.transport: rpc / mq` |
| 审计归集 | audit/record | audit 面配置 |
| 异步任务（后端自持任务状态） | task/create + task/poll | face=task + 委托形态（见 §4.8；哑上游任务 API **无需**实现） |

不实现的面不要在网关 yml 里启用（网关启动期校验开关与能力的交集，配置错误直接启动失败）。

## 3. 通用约定（每个端点都必须遵守）

### 3.1 信封与成败判定

- 所有响应 **HTTP 200 + 6 字段信封**：`{code, message, data, error, trace_id, timestamp}`；`code=0` 成功。
- 业务失败也回 HTTP 200 + 信封非 0 code（如凭证无效 = `{"code":10202,...}`）。
- **HTTP 5xx / 超时 = 基础设施故障**，网关会重试或触发 saga 补偿（退款），不要用 5xx 表达业务错误。

### 3.2 错误码（你回给网关 → 网关透传给调用方）

| code | 场景 | 必回面 |
|---|---|---|
| 10200/10202 | 凭证过期/无效 | token-validate |
| 10400 | 模型无可用渠道/不存在 | route |
| 10617 | 余额不足 | billing/pre-consume |
| 10100~10106 | 请求参数错误 | 全部 |

### 3.3 链路与幂等

- 请求头 `X-Trace-Id` 必须透传，并在信封 `trace_id` 字段回同值——排障全靠它。
- **settle / refund / access-log / audit 必须幂等**：同 `pre_consume_id` / `(trace_id, ts)` 重复请求返回首次结果，不得重复扣退。
- 超时预算（网关侧，你的服务应快于此）：route 3s / moderation 2s / billing 5s / 日志审计异步不限。

### 3.4 鉴权（网关调你时的三种方式，按网关 yml `auth:` 配置）

> 安全口径权威定义见《04_后端服务对接安全契约方案》（场景分级/逐请求签名/凭证轮换/验收清单），本节为校验摘要。

| auth | 网关发送 | 推荐级别 | 你的校验方法 |
|---|---|---|---|
| `jwt` | `Authorization: Bearer <HS256 JWT>` | **推荐（默认）** | 验签三步：① 用共享 secret 验 HS256 签名 ② 校验 `exp` 未过期 ③ 校验 `iss`/`caller` 符合约定（现网 internal-token claims：`iss=mmagix, caller=gateway-webflux, tenant_id, user_id`）；**后端换 secret 必须通知网关同步重铸**。跨网段场景网关侧可升级逐请求签名（HMAC 四头，防重放） |
| `key` | `X-API-Key: <key>` | 可用（内网限定） | 恒定时间比较静态 key（勿用普通 equals 防时序侧信道） |
| `none` | 无头 | 受限可用 | **仅 localhost/sidecar 同机隔离**；白名单/网络策略作纵深防御，同网段横向移动挡不住，勿单独依赖 |

校验失败回 HTTP 401 + 信封（code=10300），网关将其视为配置错误告警而非调用方错误。`auth=none` 且 url 非 localhost 时网关启动告警。

## 4. 能力面契约逐面说明

> 字段级完整定义见同目录 `03_能力面接口契约.yaml`，此处列语义要点。

### 4.1 token-validate — `POST /gw/v1/token/validate`

- 入：`{credential}`（调用方原始凭证，网关原样转交）。
- 出：`data: {tenant_id, user_id, active, masked_credential}`。
- 无效/过期 → 信封 10202/10200（**不是 5xx**）。
- 高频热点面：建议本地缓存（60s TTL）+ 禁用即时失效（收到禁用通知或短 TTL 权衡）。

### 4.2 route — `POST /gw/v1/route/resolve`

- 入：`{model, tenant_id, request_id}`。
- 出：`data: {candidates: [...]}`，每个候选 `{base_url, credential, credential_type, protocol, model_mapping, priority}`；网关按 priority failover。
- **上游出站凭证脱敏返回**（如可透传明文则标注 `credential_type: plain`，由网关决定是否日志脱敏）；`model_mapping` 为空 = 同名直转。
- 无可用渠道 → 信封 10400。

### 4.3 billing — 三端点（saga 三件套，`billing: direct` 时）

| 端点 | 语义 | 幂等键 |
|---|---|---|
| `POST /gw/v1/billing/pre-consume` | 预扣：余额不足回 **10617**；成功回 `{pre_consume_id, amount}` | trace_id |
| `POST /gw/v1/billing/settle` | 结算：按实际 usage 收支差额；**必须幂等** | pre_consume_id |
| `POST /gw/v1/billing/refund` | 补偿：全额退预扣（上游全失败/超时）；**必须幂等** | pre_consume_id |

saga 保证：每个 trace 最终恰好吃掉 预扣−退款 = 实际消费；你侧对账口径 = 按事件重放。

### 4.4 moderation — `POST /gw/v1/moderation/scan`

- 入：`{content, content_type}`；出：`data: {action: PASS|BLOCK|SANITIZE, sanitized_content, reason}`。
- 你的服务超时/5xx → 网关按 `fail-open` 配置决定放行或拦截——**不会重试拖慢主链路**。
- BLOCK/SANITIZE 的判定样本建议回传审计面留痕。

### 4.5 access-log — RPC 或 MQ 二选一

- **rpc**：`POST /gw/v1/access-log/record`，网关异步批量推送（不阻塞主链路，失败 quiet + 告警）。
- **mq**：见 §5，你作为消费者。
- 日志条目核心字段：`trace_id, tenant_id, user_id, model, path, prompt_tokens, completion_tokens, cached_tokens, credit, latency_ms, status, ts`。

### 4.6 audit — `POST /gw/v1/audit/record`

- 安全/管理事件外发（租户/密钥生命周期、审核拦截、配置变更）；失败不阻塞主链路。
- 你侧应 append-only 落库（禁物理删除），保留期按合规要求。

### 4.7 models — `GET /gw/v1/models`

- 出：`data: {object: "list", data: [{id, owned_by}]}`；`id` 即调用方请求的 model 名，路由绑定通配匹配的输入。

### 4.8 task 委托面（可选 — `POST /gw/v1/task/create` + `POST /gw/v1/task/poll`）

任务域有两种形态，**多数后端两种都不用实现**：

| 形态 | 谁持有任务状态 | 你要实现什么 |
|---|---|---|
| **网关本地状态机**（默认） | 网关（face-task）：经 route 面解析你的上游后，网关直接驱动你上游的 create/poll，并负责终态保障/notify/资源代理 | 无 task 面——你的上游只需提供"哑"任务 API（POST 创建 + GET 查询） |
| **委托面** | 你的后端（你本身是任务平台） | 本节两个端点 |

委托面语义：

- `task/create`：入 `{task_no, model, params, notify_url, trace_id}`（task_no 由网关生成并预扣后下发）；出 `data: {accepted, status}`。创建失败回业务 code（如 10004），网关将全额退款并置任务 FAILED。
- `task/poll`：入 `{task_no}`；出 `data: {status: PENDING|RUNNING|SUCCEEDED|FAILED|EXPIRED, result: {resources[], usage}}`。
- **幂等**：同 task_no 重复 create 返回首次结果；poll 只读。
- 资源代理与 notify 回调始终由网关承接（sig 签名 + 上游 URL 不透传语义不变），你的 result.resources 返回原始资源 URL 即可。

## 5. MQ 日志接入（`transport: mq`）

网关将访问日志异步投递到 MQ，你作为消费者落库：

| 项 | 约定 |
|---|---|
| MQ 类型 | `kafka` / `rocketmq` 二选一（网关 yml `access-log.mq.type`） |
| topic | `token-gateway-access-log`（yml 可改） |
| 分区/顺序键 | `trace_id`（同请求日志有序；跨请求不保证） |
| 投递语义 | **at-least-once**——你会收到重复消息，按 `(trace_id, ts)` 幂等去重 |
| 消息体 | JSON，与 `access-log/record` 的 `data` 同构 + `gw_sent_at`（网关投递时间戳） |
| 丢失窗口 | broker 故障时网关本地缓冲重试，超限落本地文件兜底——对账以网关侧内存计数 + 本地兜底文件为准 |

消费端伪代码：

```
for msg in consumer:
    entry = json.loads(msg.value)
    if not exists(trace_id=entry.trace_id and ts=entry.ts):   # 幂等去重
        insert access_log(entry)
    ack()
```

## 6. 最小接入走查（Go 示例，三个端点）

```go
package main

import (
    "encoding/json"
    "net/http"
)

func env(code int, msg string, data any) map[string]any {
    return map[string]any{"code": code, "message": msg, "data": data,
        "error": nil, "trace_id": "", "timestamp": nowMs()}
}

func main() {
    mux := http.NewServeMux()

    mux.HandleFunc("/gw/v1/token/validate", func(w http.ResponseWriter, r *http.Request) {
        // 生产：校验 X-API-Key / JWT；此处演示最小形状
        write(w, env(0, "success", map[string]any{
            "tenant_id": "9001", "user_id": "u1", "active": true, "masked_credential": "sk-****abcd"}))
    })

    mux.HandleFunc("/gw/v1/route/resolve", func(w http.ResponseWriter, r *http.Request) {
        write(w, env(0, "success", map[string]any{
            "candidates": []any{map[string]any{
                "base_url": "https://api.acme.io", "credential": "acme-key",
                "credential_type": "plain", "protocol": "openai",
                "model_mapping": nil, "priority": 1}}}))
    })

    mux.HandleFunc("/gw/v1/models", func(w http.ResponseWriter, r *http.Request) {
        write(w, env(0, "success", map[string]any{
            "object": "list", "data": []any{map[string]any{"id": "acme-mini", "owned_by": "acme"}}}))
    })

    http.ListenAndServe(":9500", mux)
}

func write(w http.ResponseWriter, body map[string]any) {
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(body)
}
```

联调序列（网关 yml 指向 `http://localhost:9500`，`adapter: openapi`，`billing: passthrough`）：

```bash
curl -s http://localhost:9401/v1/models -H "Authorization: Bearer test"      # 走你的 models 面
curl -s http://localhost:9401/v1/chat/completions \
  -H "Authorization: Bearer test" -H "Content-Type: application/json" \
  -d '{"model":"acme-mini","messages":[{"role":"user","content":"hi"}]}'     # 走 validate + route → 直转你的上游
```

## 7. 验收清单

- [ ] 全部响应 HTTP 200 + 信封；业务错误在 code，不用 5xx 表达
- [ ] `X-Trace-Id` 透传 + 信封 `trace_id` 回同值
- [ ] settle/refund/日志幂等（重复请求同结果）
- [ ] 鉴权按 §3.4 校验（key/token 恒定时间比较；jwt 验签+exp+iss）
- [ ] token-validate 高频面有缓存策略且禁用可即时生效
- [ ] route 候选按 priority 排序，无候选回 10400 信封
- [ ] MQ 消费（如选）幂等去重 + 消费 lag 监控
- [ ] 与网关联调：validate 失败/无路由/余额不足三向量各验一遍

## 8. FAQ

| 现象 | 根因 | 处置 |
|---|---|---|
| 网关启动失败提示能力缺失 | yml 开启的面你未实现 | 关闭该面或补实现（§2 子集表） |
| settle 收到重复请求 | 网关超时重试 | 正常——按 pre_consume_id 幂等返回首次结果 |
| 你的 5xx 导致调用方收到 10004 | 网关把基础设施故障判为上游全失败 | 业务错误一律走信封 code（§3.1） |
| MQ 日志重复 | at-least-once 语义 | 按 (trace_id, ts) 去重（§5） |
| 换 JWT secret 后网关全 401 | 两端 secret 不同步 | 后端/网关同步重铸（§3.4） |
