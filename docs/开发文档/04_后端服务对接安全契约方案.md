## 1. 角色与信任边界

```
调用方 ──(A) 调用方凭证──▶ token-gateway ──(B) 网关↔后端凭证──▶ 能力面后端
```

本文约束的是 **(B) 段**：网关作为客户端、能力面后端作为服务端的服务间调用安全。
(A) 段（调用方凭证）只要求一件事贯穿本文：**凭证不落日志**（见 §6）。

信任边界判定：任何跨主机调用都不可假设网络安全，安全必须由协议层保证（鉴权三式）；
网络层控制（端口不暴露 / 安全组 / IP 白名单）是**纵深防御**，不是替代品。

## 2. 部署场景分级

| 场景 | 定义 | 最低要求 |
|---|---|---|
| S1 同机隔离 | 后端与网关同机/同 Pod，端口绑 127.0.0.1 | `none` 可用 |
| S2 内网跨主机 | 同一受信内网，端口仅内网可达 | `key` 可用，`jwt` 推荐 |
| S3 跨网段/公网 | 跨安全域、跨云、公网 | **必须 `jwt`**；且应升级逐请求签名（§4） |

## 3. 鉴权三式契约

> 网关 yml 每能力面 `auth:` 单选。校验失败回 **HTTP 401 + 信封 code=10300**，
> 网关视为**配置错误告警**（非调用方错误），触发运维告警而非重试。

### 3.1 `jwt`（推荐，默认）

**发送**：`Authorization: Bearer <HS256 JWT>`

**claims 约定**（对齐现网 internal-token 形态）：

| claim | 含义 | 示例 |
|---|---|---|
| `iss` | 签发方 | `mmagix` |
| `caller` | 调用方身份 | `gateway-webflux` / `token-gateway` |
| `tenant_id` | 租户上下文 | `0` |
| `exp` / `iat` | 过期 / 签发时间 | 较短 exp + 定期轮换 |

**后端验签三步**：① 共享 secret 验 HS256 签名 → ② 校验 `exp` 未过期 → ③ 校验 `iss`/`caller` 符合约定。

**价值**：有调用方身份语义（审计可按 caller 归因）、有过期、可差异化授权；现网已是此形态，对齐成本为零。

**已知限制（必须周知）**：现网形态为**固定签名 JWT**（一次签好长期使用）——能防"无凭证者"，**不防截取后重放**。内网（S2）可接受；S3 必须升级 §4 逐请求签名。

**轮换纪律**：后端换 secret **必须通知网关同步重铸**（两端不同步 = 全面 401，见手册 FAQ）；建议保留双 secret 灰度窗口（新旧并行验签一个轮换周期）。

### 3.2 `key`（可用，内网 S2 限定）

**发送**：`X-API-Key: <静态 key>`

**校验**：**恒定时间比较**（勿用普通 `equals`/`==`，防时序侧信道；Java 用 `MessageDigest.isEqual`，Go 用 `subtle.ConstantTimeCompare`）。

**限制**：无身份语义（不知谁在调）、无过期、轮换需两端同步改——**禁用于 S3**。

### 3.3 `none`（受限，仅 S1）

**发送**：无鉴权头。

**适用**：仅限 localhost/sidecar 同机隔离（端口绑 127.0.0.1 + 网络策略兜底）。
IP 白名单可作为纵深叠加，但**单独使用白名单不构成认证**——它挡不住同网段被攻破后的横向移动。

**启动期强制检查**：`auth=none` 且 url 非 localhost/127.0.0.1 → 网关启动告警（`CapabilityValidator` warning）。

### 3.4 选择矩阵

| 你的场景 | 选择 |
|---|---|
| 同机 sidecar / 同 Pod | `none`（+ 端口绑定约束） |
| 内网服务间，无身份需求 | `key` 可用 |
| 内网服务间，需要审计归因/租户语义 | `jwt`（推荐） |
| 跨网段 / 公网 | `jwt` + §4 逐请求签名 |
| ~~静态不透明令牌（token 式）~~ | **已移除**（2026-08-31 决议）：既有系统迁移时按 `jwt` 重铸 |

## 4. 跨网段升级：逐请求签名（HMAC 四头）

S3 场景在 `jwt` 身份之上叠加逐请求签名，防重放防篡改。契约形状 = THMP 契约面已验证形态（`ThmpSignature`，fwk4j-signature 语义）：

**请求四头**：

| Header | 内容 |
|---|---|
| `X-Access-Key` | 调用方标识（client-id） |
| `X-Timestamp` | 毫秒时间戳（服务端校验 ±5min 时钟窗） |
| `X-Nonce` | 一次性随机串（服务端 Redis 去重，10min 窗口，重放即拒） |
| `X-Signature` | `Base64(HMAC-SHA256(secret, stringToSign))` |

**待签名串**（`\n` 连接，body 先行 MD5 保字节一致）：

```
stringToSign = HTTP_METHOD + "\n" + PATH + "\n" + TIMESTAMP + "\n" + NONCE + "\n" + md5Hex(BODY)
```

**服务端校验顺序**：签名 → 时钟窗 → nonce 一次性（任一失败回 401+10300）。所有比较恒定时间。

> 该形态在网关联 TokenHub 时是 `adapter=tokenhub` 的协议形状（配置在 `route:` 面），
> 不属于三式配置项；S3 的三方后端接入建议复用同一契约（能力面契约 yaml 已含）。

## 5. 凭证生命周期纪律

| 纪律 | 要求 |
|---|---|
| 注入 | 一律环境变量注入，**禁入仓**（含示例值也要是占位符） |
| 展示 | 日志/管理面只出现掩码（前 4 + 后 4，中间 `****`） |
| 存储 | 后端侧凭证入库走 AES-GCM cipher（cipher_by_biz 同构），禁明文落库 |
| 比较 | 一切密钥比较用恒定时间实现 |
| 轮换 | jwt secret 双密钥灰度轮换；泄露即吊销重铸，并审计泄露窗口内调用 |
| 分发 | 禁止经 IM/邮件明文传递；用密钥管理系统或加密通道 |

## 6. 调用方凭证保护（A 段纪律，贯穿 B 段）

- 调用方凭证（token / sk- key）**只进 `TokenValidator.validate` 入参**，不出现在任何日志、异常消息、审计载荷中。
- `TokenContext.toString()` 必须脱敏（SPI 铁律 4，`gateway-spi` 已内置实现）；后端 token-validate 面只回 `masked_credential`。
- 后端/网关日志中命中凭证字段时统一以掩码形态落盘。

## 7. 错误语义

| 情形 | 响应 | 网关侧处置 |
|---|---|---|
| 后端校验网关凭证失败 | HTTP 401 + 信封 `code=10300` | 视为**配置错误**，触发运维告警，不重试、不归咎调用方 |
| 网关校验调用方凭证失败 | HTTP 401 + 信封 `10200/10202` | 正常业务流，透传调用方 |
| 签名时钟窗超差 / nonce 重放 | HTTP 401 + 信封 `code=10300` | 配置错误告警（疑似重放需安全审计） |

## 8. 审计与合规

- 凭证生命周期事件（创建/轮换/吊销）、鉴权失败风暴、审核拦截 → 审计面外发（AUDIT 能力面）。
- 审计存储 append-only，禁物理删除；保留期按合规要求。
- 安全事件外发失败不阻塞主链路（quiet + 告警）。
